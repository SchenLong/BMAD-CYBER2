## Overview

BMAD-CYBER2 can integrate with various external tools and platforms to enhance workflow automation, data sharing, and team collaboration. This guide covers integration patterns for common tools including version control, project management, communication platforms, and CI/CD systems.

## Integration Architecture

### Integration Points

BMAD-CYBER2 provides several integration points:

| Integration Point | Purpose | Mechanism |
|-------------------|---------|-----------|
| Hooks | Pre/post tool execution | Shell scripts |
| Artifact Export | Share outputs | File-based + API |
| Webhook Triggers | External notifications | HTTP POST |
| LLM Providers | AI backend switching | Configuration |
| MCP Servers | Extended capabilities | Model Context Protocol |

### Integration Flow

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│  BMAD-CYBER2    │───►│  Integration     │───►│  External       │
│  Workflow       │    │  Layer           │    │  System         │
└─────────────────┘    └──────────────────┘    └─────────────────┘
        │                      │                       │
        ▼                      ▼                       ▼
   Artifacts           Hooks/Webhooks             Jira/GitHub/
   (.md, .yaml)        Shell Scripts              Slack/etc.
```

## GitHub Integration

### Repository Synchronization

Sync artifacts to a GitHub repository:

```bash
#!/bin/bash
# sync-to-github.sh

ARTIFACT_DIR="_bmad-output"
REPO_DIR="$HOME/artifact-repo"

# Ensure repo exists
if [ ! -d "$REPO_DIR/.git" ]; then
    git clone git@github.com:org/bmad-artifacts.git "$REPO_DIR"
fi

# Sync artifacts
rsync -av --delete "$ARTIFACT_DIR/" "$REPO_DIR/artifacts/"

# Commit and push
cd "$REPO_DIR"
git add .
git commit -m "Artifact sync: $(date +%Y-%m-%d %H:%M)"
git push origin main
```

### GitHub Issues from Findings

Convert vulnerability findings to GitHub issues:

```bash
#!/bin/bash
# create-issues.sh

FINDINGS_FILE="$1"

# Requires: gh CLI authenticated
# Requires: yq for YAML parsing

for finding in $(yq e '.findings[].id' "$FINDINGS_FILE"); do
    title=$(yq e ".findings[] | select(.id == \"$finding\") | .title" "$FINDINGS_FILE")
    description=$(yq e ".findings[] | select(.id == \"$finding\") | .description" "$FINDINGS_FILE")
    severity=$(yq e ".findings[] | select(.id == \"$finding\") | .severity" "$FINDINGS_FILE")
    remediation=$(yq e ".findings[] | select(.id == \"$finding\") | .remediation" "$FINDINGS_FILE")

    # Create issue body
    body=$(cat <<EOF
## Description
$description

## Severity
$severity

## Remediation
$remediation

---
*Generated by BMAD-CYBER2*
EOF
)

    # Create GitHub issue
    gh issue create \
        --repo "org/security-findings" \
        --title "[$severity] $title" \
        --body "$body" \
        --label "security,$severity,automated"

    echo "Created issue for: $finding"
done
```

## Jira Integration

### Export Findings to Jira

Create Jira issues from security findings:

```bash
#!/bin/bash
# export-to-jira.sh

JIRA_URL="https://yourorg.atlassian.net"
JIRA_USER="user@example.com"
JIRA_TOKEN="$JIRA_API_TOKEN"
PROJECT_KEY="SEC"
FINDINGS_FILE="$1"

# Map severity to Jira priority
map_priority() {
    case $1 in
        critical) echo "Highest" ;;
        high) echo "High" ;;
        medium) echo "Medium" ;;
        low) echo "Low" ;;
        *) echo "Lowest" ;;
    esac
}

# Process each finding
for finding in $(yq e '.findings[].id' "$FINDINGS_FILE"); do
    title=$(yq e ".findings[] | select(.id == \"$finding\") | .title" "$FINDINGS_FILE")
    description=$(yq e ".findings[] | select(.id == \"$finding\") | .description" "$FINDINGS_FILE")
    severity=$(yq e ".findings[] | select(.id == \"$finding\") | .severity" "$FINDINGS_FILE")
    priority=$(map_priority "$severity")

    # Create Jira issue
    payload=$(cat <<EOF
{
    "fields": {
        "project": {"key": "$PROJECT_KEY"},
        "summary": "[$severity] $title",
        "description": "$description\n\n---\n_Generated by BMAD-CYBER2_",
        "issuetype": {"name": "Bug"},
        "priority": {"name": "$priority"},
        "labels": ["security", "automated", "$severity"]
    }
}
EOF
)

    curl -X POST \
        -H "Content-Type: application/json" \
        -u "$JIRA_USER:$JIRA_TOKEN" \
        -d "$payload" \
        "$JIRA_URL/rest/api/3/issue"

    echo "Created Jira issue for: $finding"
done
```

## Slack Integration

### Workflow Notifications

Send notifications when workflows complete:

```bash
#!/bin/bash
# slack-notify.sh

SLACK_WEBHOOK_URL="$SLACK_WEBHOOK"
WORKFLOW_NAME="$1"
STATUS="$2"
DETAILS="$3"

# Choose emoji based on status
case $STATUS in
    success) emoji=":white_check_mark:" ;;
    warning) emoji=":warning:" ;;
    failure) emoji=":x:" ;;
    *) emoji=":information_source:" ;;
esac

# Build message
payload=$(cat <<EOF
{
    "blocks": [
        {
            "type": "header",
            "text": {
                "type": "plain_text",
                "text": "$emoji BMAD Workflow: $WORKFLOW_NAME"
            }
        },
        {
            "type": "section",
            "fields": [
                {
                    "type": "mrkdwn",
                    "text": "*Status:*\n$STATUS"
                },
                {
                    "type": "mrkdwn",
                    "text": "*Time:*\n$(date '+%Y-%m-%d %H:%M')"
                }
            ]
        },
        {
            "type": "section",
            "text": {
                "type": "mrkdwn",
                "text": "$DETAILS"
            }
        }
    ]
}
EOF
)

curl -X POST \
    -H "Content-Type: application/json" \
    -d "$payload" \
    "$SLACK_WEBHOOK_URL"
```

## Webhook Configuration

### Outgoing Webhooks

Configure BMAD to send webhooks on events:

```yaml
# In config.yaml
webhooks:
  enabled: true
  endpoints:
    - url: "https://hooks.slack.com/services/XXX"
      events: ["workflow_complete", "critical_finding"]
      format: "slack"

    - url: "https://yourorg.atlassian.net/webhook"
      events: ["workflow_complete"]
      format: "jira"
      auth:
        type: "basic"
        username_env: "JIRA_USER"
        password_env: "JIRA_TOKEN"
```

### Webhook Handler Hook

Create a hook to fire webhooks:

```bash
#!/bin/bash
# .claude/hooks/webhook-handler.sh

EVENT_TYPE="$1"
EVENT_DATA="$2"

# Read webhook config
WEBHOOKS=$(yq e '.webhooks.endpoints[]' _bmad/core/config.yaml)

# Send to each configured endpoint
echo "$WEBHOOKS" | while read -r webhook; do
    url=$(echo "$webhook" | yq e '.url' -)
    events=$(echo "$webhook" | yq e '.events[]' -)

    # Check if this event should trigger
    if echo "$events" | grep -q "$EVENT_TYPE"; then
        curl -X POST \
            -H "Content-Type: application/json" \
            -d "$EVENT_DATA" \
            "$url"
    fi
done
```

## MCP Server Integration

### Available MCP Servers

BMAD-CYBER2 can leverage MCP (Model Context Protocol) servers for extended capabilities:

| MCP Server | Purpose | Use Case |
|------------|---------|----------|
| Filesystem | Enhanced file access | Large file operations |
| Memory | Persistent context | Cross-session state |
| GitHub | Direct GitHub access | PR creation, issue management |
| PostgreSQL | Database access | Data querying |
| Brave Search | Web search | Research workflows |

### Configuring MCP Servers

In `.claude/settings.json`:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}"
      }
    },
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "POSTGRES_CONNECTION_STRING": "${DATABASE_URL}"
      }
    },
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "${BRAVE_API_KEY}"
      }
    }
  }
}
```

## Custom Hook Integration

### Hook Architecture

Hooks execute at specific points in tool execution:

```
_bmad/hooks/
├── pre-tool/           # Before tool execution
│   ├── validate-input.sh
│   └── log-request.sh
├── post-tool/          # After tool execution
│   ├── export-result.sh
│   └── notify-slack.sh
└── on-error/           # On tool errors
    └── alert-team.sh
```

### Creating Integration Hooks

```bash
#!/bin/bash
# .claude/hooks/post-tool/export-to-external.sh

# This hook runs after each tool execution
TOOL_NAME="$1"
TOOL_RESULT="$2"

# Check if this is a workflow completion
if [[ "$TOOL_NAME" == "workflow" && "$TOOL_RESULT" == *"complete"* ]]; then
    # Export artifacts
    ./scripts/sync-to-github.sh

    # Notify team
    ./scripts/slack-notify.sh "Workflow" "complete"

    # Create tracking ticket
    ./scripts/create-jira-ticket.sh "$TOOL_RESULT"
fi
```

## API Integration Patterns

### REST API Export

Export artifacts via REST API:

```python
# api_export.py
import os
import requests
import yaml
from pathlib import Path

class BMADArtifactExporter:
    def __init__(self, api_url, api_key):
        self.api_url = api_url
        self.headers = {"Authorization": f"Bearer {api_key}"}

    def export_findings(self, findings_file):
        """Export findings to external API."""
        with open(findings_file) as f:
            findings = yaml.safe_load(f)

        for finding in findings.get('findings', []):
            response = requests.post(
                f"{self.api_url}/findings",
                headers=self.headers,
                json=finding
            )
            if response.status_code == 201:
                print(f"Exported: {finding['id']}")
            else:
                print(f"Failed: {finding['id']} - {response.status_code}")

    def export_report(self, report_file):
        """Export full report to external API."""
        with open(report_file) as f:
            report_content = f.read()

        response = requests.post(
            f"{self.api_url}/reports",
            headers=self.headers,
            json={
                "filename": os.path.basename(report_file),
                "content": report_content,
                "format": "markdown"
            }
        )
        return response.json()

# Usage
exporter = BMADArtifactExporter(
    os.environ["API_URL"],
    os.environ["API_KEY"]
)
exporter.export_findings("_bmad-output/findings.yaml")
```

### GraphQL Integration

```python
# graphql_export.py
import requests

GRAPHQL_ENDPOINT = "https://api.example.com/graphql"

def create_finding(finding):
    """Create finding via GraphQL mutation."""
    mutation = """
    mutation CreateFinding($input: FindingInput!) {
        createFinding(input: $input) {
            id
            status
            url
        }
    }
    """

    variables = {
        "input": {
            "title": finding["title"],
            "severity": finding["severity"],
            "description": finding["description"],
            "remediation": finding["remediation"],
            "source": "BMAD-CYBER2"
        }
    }

    response = requests.post(
        GRAPHQL_ENDPOINT,
        json={"query": mutation, "variables": variables},
        headers={"Authorization": f"Bearer {API_KEY}"}
    )

    return response.json()
```

## Troubleshooting

| Issue | Cause | Solution |
|-------|-------|----------|
| Webhook not firing | Wrong event type | Verify event name in config |
| API auth failed | Token expired | Refresh API token |
| Hook timeout | Slow external API | Increase timeout in settings |
| Missing data | Export path wrong | Check artifact locations |
| Slack not receiving | Webhook URL invalid | Regenerate Slack webhook |
| Jira creation fails | Missing required fields | Check Jira project settings |

## Security Considerations

### Credential Management

- Never hardcode credentials in scripts
- Use environment variables for secrets
- Rotate API keys regularly
- Use service accounts for CI/CD

### Data Protection

- Encrypt data in transit (HTTPS)
- Sanitize sensitive data before export
- Respect data classification levels
- Log integration activities for audit

### Access Control

- Limit webhook endpoints to trusted systems
- Use API keys with minimal required permissions
- Implement IP allowlisting where possible
- Monitor for unusual integration activity
