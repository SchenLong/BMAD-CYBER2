# BMAD-METHOD vs BMAD-CYBERSEC Comparison

This document provides a comprehensive comparison between the [original BMAD-METHOD framework](https://github.com/bmad-code-org/BMAD-METHOD) and the BMAD-CYBERSEC module collection.

---

## Executive Summary

BMAD-CYBERSEC extends the original BMAD-METHOD framework with **4 specialized teams** for cybersecurity, intelligence, executive strategy, and legal domains, while maintaining full compatibility with the core development modules.

| Metric | BMAD-METHOD | BMAD-CYBERSEC | Change |
|--------|-------------|-------------|--------|
| Agents | ~22 | 78 | +256% |
| Workflows | ~50 | 88 | +76% |
| Modules | 3 | 9 | +6 specialized |
| Party Mode Presets | — | 27 | New feature |

## When to Use Which

### Use BMAD-METHOD When:

- Pure software development with no security/intel/strategy needs
- Game development projects
- Simple agent/workflow creation
- Smaller footprint preferred
- No need for specialized teams

### Use BMAD-CYBERSEC When:

- Need cybersecurity capabilities (IR, pentest, compliance, forensics)
- Need intelligence operations (OSINT, HUMINT, SIGINT)
- Need executive strategy support (14 advisors, 8 archetypes)
- Need legal coordination (4 jurisdictions)
- Need cross-module collaboration (27 party presets)
- Processing privacy-sensitive data (local LLM routing)
- Require security framework compliance (NIST, MITRE, ISO, 20+)
- Need domain-trained models for specialized tasks

---

## Migration Path

BMAD-CYBERSEC is **backwards compatible** with BMAD-METHOD. Existing BMM, BMB, CIS, and BMGD workflows will work without modification.

To add specialized capabilities:
1. Clone BMAD-CYBERSEC repository
2. Existing workflows continue to work
3. New specialized agents available immediately
4. Configure local LLM routing as needed
